# src/components/onboarding/home-page rules
- One home's Onboarding view (/onboarding/$propertyId) is composed from src/components/onboarding/home-page over pure rules in src/lib/onboarding-home-page.ts (tabs, computed stage, Status to stage map, schedule health, whose Task, Needs attention, Add task permission); Add task goes only through addStageTask with the plan catch-up viewer; selection reuses PlanCatchUpBar. Why: one rule per behavior, the Operations view and Director hub stay separate.
- Part 3 tabs (Home details, Files, Vendors and work) compose src/components/onboarding/home-details, home-files and home-vendors over pure rules in src/lib/home-details.ts; every upload on a home picks one of the five Files folders (never Other) and Task files are saved straight into the picked folder by the upload step itself (no second filing step); the temporary More tab is retired and old tab links map through oldTabPlace. Why: one rule per behavior, one upload path, no duplicate field homes.
- Tasks tab Due buttons: the match rule lives only in matchesDueFilters (src/lib/onboarding-home-page.ts, Overdue via rowDue, weeks via myTasksWeeks) and stageLists takes it as an input; the selection is page state, never saved. Why: one rule, same red date and week bounds as My Tasks.
